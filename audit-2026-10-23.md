## Подтверждённые недочёты и предложения

### 1. Нажатие на короткую задачу может открыть соседнюю — исправить в первую очередь

**Статус: исправлено и проверено 23 октября.** Независимые зоны кнопки и галочки, колонки по областям взаимодействия, сохранение настоящих времени и высоты; при высокой плотности — прокрутка внутри расписания.

**Основание:** `tz.md`, §7.3, §8.2 и AT-39: соседние элементы не перекрываются, у короткого интервала есть доступная кнопка открытия.

**Воспроизведение:** шесть последовательных задач по пять минут с 10:00 до 10:30. Высота каждой карточки около 4,66 px при шкале 56 px/час, а минимальная высота её кнопки — 18 px. Кнопки выступают за интервалы и перекрываются. Настоящий щелчок в центре первой карточки открыл форму «Короткая 3» вместо «Короткая 1».

**Где:** `style.css:3`, правила `.timeline-task.compact` и `.task-open`; `script.js:610`, включение компактного вида.

**Доделать:** развести подписи и области нажатия коротких задач, сохранив привязку к настоящему времени. Каждая карточка должна отдельно открываться и отмечаться мышью, включая плотную последовательность интервалов по 1, 5 и 10 минут. Добавить проверку фактической цели щелчка, а не только наличия кнопки в DOM.

### 2. Повторное включение серии после объединения иногда не сохраняется

**Статус: исправлено и проверено 23 октября.** Старые объединения отсоединяются с сохранением исключений от повторной генерации; идентичность задачи и выполненная история сохранены.

**Основание:** §12.4–12.5, §14.5 и согласованное пользователем включение повторения у уже сохранённой обычной задачи.

**Воспроизведение:** создать будничную серию → выполнить первую задачу → дождаться следующего выполнения → вернуть первую в работу, объединив её со следующей → прекратить повторение → у оставшейся обычной задачи выбрать недельный повтор. В интерфейсе остаётся открытая форма и сообщение «Не удалось сохранить: неверные данные»; новое правило не записывается.

**Причина:** старые внутренние записи объединения продолжают ссылаться на задачу, которая присоединяется уже к новой серии. Итог не проходит собственную валидацию. Прежние данные при проверке не были перезаписаны.

**Где:** `script.js:211` (`saveTask`), `script.js:279` (`stopSeries`), `script.js:330` (`validState`).

**Доделать:** согласовать отвязку старых объединений при создании новой серии, сохранив историю и запреты повторной генерации. Проверять полный цикл «объединить → прекратить → включить новое правило», а не только прекращение отдельно.

### 3. Проверка копии пропускает конфликт с ID будущего повтора

**Статус: исправлено и проверено 23 октября.** Копия с конфликтом сохранённого ID и будущего вычисляемого выполнения отклоняется целиком; корректные прежние ID остановленных серий принимаются.

**Основание:** §14.4–14.5 и §16.2: стабильная идентичность выполнения, уникальность ID и проверка ссылок при импорте.

**Воспроизведение:** в искусственно составленной копии обычной задаче назначен ID, совпадающий с ID ещё не сохранённого будущего выполнения другой серии. Среди сохранённых задач дубля нет, поэтому `validState` и `parseBackup` принимают файл. Календарь показывает будущий повтор, но `getTask` по этому ID возвращает другую обычную задачу на сегодня.

Это редкий случай некорректной внешней/вручную изменённой копии. Обычным добавлением задачи такой ID не вводится.

**Где:** `script.js:132` (`virtualTask`), `script.js:137` (`getTask`), `script.js:330` (`validState`).

**Доделать:** проверять конфликты сохранённых ID с вычисляемыми ID будущих выполнений и идентичность открываемой задачи. Учитывать допустимые ID задач, превращённых из серии в обычные; простого запрета общего префикса недостаточно. Неверная копия должна отклоняться целиком.

### 4. Нет прямого восстановления копии при повреждённом внешнем обновлении

**Статус: исправлено и проверено 23 октября.** Файл доступен во время конфликта с явным подтверждением замены обеих версий. Отмена, отказ записи и более свежее внешнее изменение сохраняют предыдущие данные.

**Основание:** сочетание предусмотренных §15.3–15.4 сценариев повреждения и конфликта; §16.2. Базовое восстановление при повреждении на первоначальном запуске работает.

**Воспроизведение:** при открытой странице состояние изменено извне на повреждённый JSON. Приложение показывает конфликт и сохраняет свою копию. «Загрузить данные другой вкладки» отклоняет повреждённую строку; «Загрузить резервную копию» требует сначала разрешить тот же конфликт. Прямого выхода через корректную копию в текущем интерфейсе нет.

**Где:** `script.js:435` (`readState`), `script.js:502` (`chooseBackup`), `loadExternal`.

**Доделать:** после возможности скачать свою версию дать явно подтверждаемый путь полного восстановления корректного файла даже при таком конфликте. Не заменять данные молча. Нынешний обход — скачать свою копию и заново открыть страницу для перехода в первоначальное восстановление — не должен быть единственным вариантом.

### 5. Сброс на ту же дату создаёт лишнее сохранение — небольшой дефект

**Статус: исправлено и проверено 23 октября.** Сброс на исходную дату в неделе и месяце не записывает данные, не меняет ревизию/служебные поля и не сообщает о переносе. Будущие вычисляемые выполнения при этом не материализуются. Проверка внешнего состояния перед действием сохранена.

**Основание:** §10.1: перенос на ту же дату ничего не меняет, если пользователь не переставляет задачу внутри списка.

**Воспроизведение:** перетащить обычную задачу на её собственный день в неделе. Поля задачи остались прежними, но ревизия увеличилась с 0 до 1, обновился момент изменения и появилось сообщение о переносе.

**Где:** `script.js:667` (обработчик сброса на дату), `script.js:477` (`commit`).

**Доделать:** распознавать отсутствие изменения и не выполнять запись/уведомление о переносе. Добавить отдельный тест именно интерфейса, поскольку чистая функция `moveTask` уже возвращает неизменённые данные.

### 6. В расписании нет видимого признака повторения — небольшое расхождение оформления

**Статус: исправлено и проверено 23 октября.** Компактный значок ↻ виден внутри кнопки временной карточки, включая короткие, будущие и выполненные задачи. Место под него зарезервировано отдельно от времени, названия и галочки; добавлено доступное текстовое пояснение.

**Основание:** §7.3: небольшой признак повторения у задач серии.

**Факт:** значок «↻ Повторяется» показывается в «Без времени». У временной карточки его нет; сообщение о повторении доступно только в подсказке при наведении.

**Где:** `script.js:565`, условие `task.seriesId && !timeline`.

**Доделать:** добавить компактный видимый признак повтора в расписании, не закрывая время, название и галочку.
